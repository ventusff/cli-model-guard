# AGENTS.md — cli-model-guard

A Claude Code plugin (`model-guard`, distributed from this repo as marketplace `cli-model-guard`): a full-width statusline band that flags a silent model downgrade, plus hooks that undo a safeguard-flag downgrade — stop the turn, type `/model` and `/effort` into the session's own terminal (tmux, zellij or kitty), resume the task. Pure bash + jq, no build step, no daemon. Installed via `/plugin marketplace add ventusff/cli-model-guard`, so `main` on GitHub is what every install fetches.

The Codex integration lives independently under `codex/model-guard/`: a valid Codex plugin and Python package, with a pinned native Codex build with metadata events, conditional footer warnings and a stop: the native guard keeps the model the user selected, declines Codex's own automatic model switches (the Luna Reserve fallback and banner fallbacks), and on a request for another model, a disclosed different model or a differently labeled response it interrupts the turn and holds every further turn until the user selects a model again. The Python app-server adapter is used only by the explicit standalone probe. See its `ROUTING.md` for evidence boundaries and primary sources. It never changes the model itself.

## Run and verify

```sh
tests/run.sh      # the whole suite (state machine, driver, channel detection, bands, install check); must end "0 failed"
```

For Codex, run from `codex/model-guard/` with Python 3.12+ and Codex 0.155.1: create a venv, install `requirements.lock` with `pip --require-hashes`, install the package with `pip --no-deps -e .`, then `PYTHONPATH=. MODEL_GUARD_INTEGRATION=1 <venv>/bin/python -m unittest discover -s tests -v`. Fixtures use isolated Codex homes and loopback servers; never use live credentials for regression tests.

Codex invariants: requested model is not observed evidence, but a request for a model other than the user's selection is a stop; absent headers stay unknown in diagnostics without a default warning; metadata is bound to thread/turn; model/account text is sanitized before native rendering. A stop interrupts through the normal `turn/interrupt` path and holds turns with the composed text returned to the composer (both `submit_op` and the app's `AppEvent::CodexOp` handler gate); it is lifted only by a manual model selection (`AppEvent::UpdateModel` or the advanced-reasoning popup), never by Codex's switch back from Reserve, which is allowed only to the selection. Selection and stop live in the process-wide per-thread registry in `model_guard.rs` (`thread_guard`, `observe_background`): a rebuilt widget inherits the selection and restores its thread's stop when configured, a turn started on a stopped thread is interrupted, and `enqueue_thread_notification` judges inactive threads and interrupts them through `AppEvent::ModelGuardInterrupt`. The guard never sends a settings update, a retry or an inference request; while it is active `backend_banner_fallback` returns no usage-limit switch, `waiting_for_luna_reserve` and the Reserve-only picker are off, and the reserve model is flagged whenever it is active. A configured `review_model` is accepted only while `review.is_review_mode`. The 516 heuristic stops only behind `halt_on_reasoning_anomaly` in the guard's `config.json`. The observer never reads auth files or writes Codex session records. Preserve stock CLI behavior for noninteractive/profile/remote invocations and preserve existing terminals during install/removal. Code changes belong in the source package, never the installed environment. No terminal wrapper or separate multiplexer is permitted for Codex. Native source patches, schema artifacts, source pin and build instructions live in `codex/model-guard/native/`; the package is built inside the `rust:1.95.0-bookworm` container so its glibc floor is 2.36. The build's `codex update` and update banner hand off to `model-guard-codex update` (patch 0006); an official installer run replaces the entry and `doctor` names the way back. Use the upstream `just test` runner for Rust checks (with `INSTA_WORKSPACE_ROOT` pointing at the tree under test) and review native terminal behavior including `cx resume`. The Codex manifest, Python package, pyproject and `native/release.json` carry one version, the one compiled into the native build; it moves only with a new native release and may trail the Claude version.

Two Codex routing signals, in rank order: the effective-model header (`server_model`; red, decides the strict verdict) and the response body's `model` label (`response_label`; orange, second tier). A label agrees with the request when equal or when one extends the other at a separator; a size tier (`mini`, `nano`, `lite`, `small`, `fast`, `flash`, `turbo`) or another family differs. The rule lives twice, in `model_guard.rs` and `state.py`, and both have the same test table. Neither signal verifies weights.

Codex reasoning telemetry is a separate heuristic: a single exact 516 at high or greater effort stays in diagnostics; at least three of five recent valid response observations produces a visible heuristic warning. Higher 518n-2 values alone do not alert. Count unique native response IDs, not repeated usage notifications. Bind statistics to model/provider/effort/tier/account, preserve in-flight settings, and distinguish fresh threads from attachments/accepted rollbacks. Strict route exit codes never incorporate a heuristic as model identity.

Requirements: bash 4+, jq and curl; the recovery path also uses `flock` and `setsid`. Tests run on the machine, not in CI — `tests/run.sh` is the bar. The two workflows under `.github/workflows/` serve the native Codex package only: `codex-upstream.yml` watches for a newer official Codex release daily and keeps an issue saying whether the patches still apply; `codex-native.yml` (manual dispatch) builds the package inside `rust:1.95.0-bookworm` from the pins in `native/release.json` and uploads it with its digests. Hooks load at session start, so a change under `hooks/` or `scripts/` is only observed by a freshly started session, and the statusline change only after the installed copy is refreshed. A running Codex process keeps the executable it started with; the installer names those sessions rather than pretending they changed.

## Hard rules

- **The version lives in three Claude places and must match**: `.claude-plugin/plugin.json`, `MG_VERSION` in `scripts/lib.sh`, the top entry of `CHANGELOG.md`; the Codex version has its own four places, which match each other: `.codex-plugin/plugin.json`, `model_guard/__init__.py`, `pyproject.toml`, `native/release.json` (`plugin_version` and the release URL). `check-install.sh` decides whether to refresh a user's installed scripts by comparing `MG_VERSION` — a release that bumps plugin.json but not `MG_VERSION` leaves every user on the old scripts, silently.
- **The installed statusline is a copy** (`~/.claude/model-guard/`). Editing anything under `scripts/` changes nothing in a running session until the copy is refreshed (session-start hook or `setup`).
- **Effort follows the active model's saved default.** Prefer `modelSettings[canonical_model].effortLevel` over the legacy global `effortLevel`; `[1m]` variants share the canonical key. Read it on each refresh. Never overwrite the user's saved effort to make an alarm disappear.
- **Config, settings, state, the install dir and the login token are resolved through the `MODEL_GUARD_*` overrides** (`MODEL_GUARD_CONF`, `MODEL_GUARD_SETTINGS`, `MODEL_GUARD_STATE_DIR`, `MODEL_GUARD_SESSIONS_DIR`, `MODEL_GUARD_INSTALL_DIR`, and `MODEL_GUARD_CREDENTIALS`, which also switches off the environment and keychain lookups) in `lib.sh`, `statusline.sh` and `check-install.sh`; the tests point them at a temp dir and put a stand-in `curl` first on `PATH`. A new read of `~/.claude/...` that bypasses them makes the suite touch the real machine or the network.
- **Hooks are silent unless they act.** Session start, upgrades, and switches from the named user-driven sources (`command`, `picker`, `sdk`, `config`, `fast_mode`, `slash_command`) produce no output and no state; every other switch source to a weaker model starts a recovery episode. The suite asserts both directions.
- **Keystrokes address one pane by id, never the focused window** — tmux `$TMUX_PANE`, zellij `terminal_<ZELLIJ_PANE_ID>`, kitty `$KITTY_WINDOW_ID`. A missing or non-numeric pane id means "no channel", not a guess.
- **A recovery never changes tomorrow's default.** `/model <id>` also writes `model` into `settings.json`; the driver restores the previous default afterwards, and the suite checks it.
- **Colours are truecolor with a 256-colour fallback, every pair >= 7:1 contrast, no blink.** No plain ANSI 16-colour codes — themes remap them and the alarm stops being an alarm.
- **`README.md` and `README.zh-CN.md` say the same thing** — change both. User-visible behaviour changes get a `CHANGELOG.md` entry.
- Comments and commit messages are English. A release is one commit titled `model-guard <version> — <what changed>`.
